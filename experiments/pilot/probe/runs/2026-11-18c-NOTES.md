# Probe run C, 18 Nov 2026: fewer rules in the prompt

Same 10 problems, model and harness as runs A and B. Two new Aleph conditions:

- **lite**: `prompts/llms-lite.txt`, about 890 tokens instead of 2,050. It drops what the formatter and the compiler handle (canonical order, formatting, diagnostics, canonical form, command line) and keeps syntax, types, expressions, builtins and the few rules that matter.
- **fewshot**: `prompts/fewshot.txt`, about 660 tokens: one paragraph of syntax, the builtins table and five solved, verified programs.

Both add "The order of functions does not matter." Answers are formatted with `aleph fmt` before testing, as in runs A and B.

Unanswered problems hung on the free endpoint or returned no code.

## What it shows

- Fewer rules cut reasoning by about two thirds (3,334 → 1,010) and bring total tokens close to Python (+14% instead of +58%).
- Accuracy drops: every new failure is a compile error the compiler names exactly: `[]` for an empty list instead of `empty T` (P001), a call with the wrong number of arguments (P002), or no code returned. None is a wrong algorithm except one infinite recursion (R004) in few-shot.
- So the rules the model stops reasoning about become errors that `aleph check` reports with node and expected value. A single round of feedback should recover most of them; that is the next thing to measure, counting its tokens.

## Limits

Ten problems, one run per condition, single shot without compiler feedback, through an agent CLI. Medians over the answered problems of each condition, not the same set.
